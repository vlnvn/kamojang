# ADR 0002: Licensed self-hosted viewer and optional loopback forecast execution

Status: accepted for implementation, 28 October 2026. Updates ADR 0001 only for the explicitly requested executable research forecast path; browser-local robust screening remains unchanged.

The owner provided `steam_turbine.zip`, containing the candidate's genuine glTF geometry and matching source/author/CC-BY-4.0 notice. Use Three.js 0.186.1 directly rather than introducing an additional React renderer abstraction. A lazy component owns one renderer, scene, fixed camera, bounded OrbitControls, local Meshopt decoder, demand-driven rendering, cancellation and disposal. The optimized asset and an actual-mesh poster are self-hosted. Geometry is not represented as Kamojang hardware. No rotor animation is invented.

The owner also explicitly requested available GPR based on the research. Reimplementing optimized GPR hyperparameters ad hoc in JavaScript or replacing the model with cached claims would not preserve the reproduced method. Reuse the existing Python/scikit-learn benchmark kernel, training-only scaling, chronological last-eight holdout and seed. Expose it through an **optional loopback-only service**, with a clearly labeled UI action. The default static app retains robust screening independently; `npm run dev:research` and `npm run preview:research` enable forecast computation.

The service binds only 127.0.0.1, validates Host/Origin/content type/body size/finite values/schema, rejects ambiguous same-date split boundaries, allows one job at a time, bounds observations to 12–256 and computation to 60 seconds, and terminates requested cancellation jobs. Per-request compute happens in a subprocess. Data is passed in memory through stdin/stdout, never persisted or logged; responses are no-store. There is no cloud endpoint, authentication system, database or auto-upload. Production static hosting alone does not provide GPR. Frontend execution is restricted to localhost, with actionable unavailable-service behavior.

The split, native-unit MAE/RMSE, baseline forecasts, optimizer warnings and uncalibrated posterior deviation are presented as **forecast evaluation**, never fault classification or validated prospective maintenance. Existing 220-score robust parity is separate and unchanged. Uploaded data still disappears on refresh. Explicit local GPR execution additionally sends normalized rows only to the service on the same device; documentation must explain this boundary rather than continue saying all computations remain solely inside the browser.
