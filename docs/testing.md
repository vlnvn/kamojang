## Measured 3D performance (A4)

`npm run build`, `npm run preview`, then `node scripts/viewer-performance.mjs --hardware` produced local production observations with reported renderer **ANGLE Intel UHD Graphics (0x0000468B), Direct3D11**. The discrete NVIDIA adapter was not used. Desktop 1600×960 DPR 1: load 1,763.2 ms, 174 browser RAF intervals over 3,533.2 ms (49.25 Hz), p95 interval 16.8 ms, click-to-two-RAF 27.5 ms. Emulated 430×932 DPR 2, renderer DPR 1.5: load 439.6 ms, 181 intervals over 3,016.6 ms (60.00 Hz), p95 16.8 ms, click-to-two-RAF 13.2 ms. No page errors were observed. An earlier run observed 59–60 Hz; the later desktop sample includes a stall and is retained rather than selecting only the favorable result. A stable 60 FPS guarantee is **not established**.

GLB encoded bytes: 1,215,756; localhost transferred 1,216,056 bytes including overhead. Resource duration was 12.1 / 10.1 ms; these are local transport timings, not internet loading promises. Renderer reports 35 draw calls, 347,400 submitted triangles including shadow/ground passes, 18 geometries and 20 textures. Asset-only rendered triangles are 173,699. GPU memory bytes are not exposed by this API. CI uses software SwiftShader solely for correctness, never physical-device FPS claims.

Main minified JS is approximately 255 kB; the lazy Three.js viewer is approximately 642 kB (161 kB gzip), plus a 26 kB decoder. Vite's >500 kB chunk warning remains visible. The viewer is deferred, but Ringkasan loads it; no unsupported claim of zero performance cost is made. A4 passes tested reliability and recorded measurements with limitations; universal hardware performance and constant 60 FPS remain unverified.
